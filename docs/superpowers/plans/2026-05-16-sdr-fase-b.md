# SDR Intelligence Module — Fase B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Entregar as skills determinísticas SDR (qualify-opportunity/PACT, segment-account/ABCD, enrich-3c), a categoria `sales`, a migration `sdr_account_state`, o seam L3 sales-state operativo, o sub-modo do MessageAnalyzer, o plumbing de `contactId`, e os tunáveis §7 — robusto e testado.

**Architecture:** Skills determinísticas read/compute como manifest skills auto-descobertas (`src/skills-builtin/sales/<name>/`). L3 sales-state NÃO é um ContextLayer (o sistema de layers é morto em produção — F1) — é injetado no seam operativo `composeSystemPrompt` em `execution-handler.ts:479`. Sub-modo emitido incondicionalmente pelo MessageAnalyzer (fail-safe, F3). Permissão V1 não-enforced é inerte para Phase B pois as 3 skills são side-effect-free (F5, invariante obrigatória nos testes).

**Tech Stack:** Node 20 / TS 5.9 ESM/NodeNext, Zod 4, Vitest 4, Postgres (pgvector testcontainers). Worktree `.claude/worktrees/sdr-impl`, branch `feat/sdr-intelligence-module`. Spec: `docs/superpowers/specs/2026-05-16-sdr-intelligence-module-design.md` §5, §7, §2.3.

## Flags da spec confirmados no código (LER PRIMEIRO)

- **F1 (hard):** o sistema de `ContextLayer`/`ContextBuilder` é **morto em produção** (só instanciado em testes). L3 sales-state deve ser injetado no seam `composeSystemPrompt` (`src/sdr/compose.ts` + `execution-handler.ts:479`), **não** como ContextLayer. Mesmo padrão das C-findings da Fase 0.
- **F2 (hard):** o `agentContext` do surface loop **nunca seta `contactId`** (`execution-handler.ts:505-523`); só é parseado para o path de RAG (875-886). `accountId` está disponível. Task T8 conserta isso e é pré-requisito de T5/T7.
- **F3 (medium):** o MessageAnalyzer roda ANTES de `sdr_profile` ser parseado. Emitir `sdrSubMode` incondicionalmente; gate-off ignora (fail-safe, §2.3).
- **F4 (low):** não há `switch` exaustivo sobre `category`. O ripple de adicionar `sales` é só 2 sites de tipo: `skill-manifest.schema.ts:48` (Zod enum) + `tools/types.ts:3` (`ToolCategory`), acoplados via `skill-registry.ts:58`. Não auditar "switches".
- **F5 (low):** o `evaluator.ts` ignora `manifest.permissions` inteiramente. Para as 3 skills read/compute o gap é inerte. Invariante obrigatória: T3/T4/T5 asseguram zero side-effect (sem DB write, sem HTTP, sem stop-signal; manifest `sideEffects:[read]` ou `[]`). Decisão de Security é pré-requisito de Phase C, não B.
